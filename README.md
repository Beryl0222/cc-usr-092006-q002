# 景区客流联动服务

面向大型景区值班室的**可独立运行**客流联动服务。它把闸机计数、线上分时票、停车区入场、
摆渡车到发、图像人数快照等不同来源、可能**迟到 / 乱序 / 重复**的事件，归并为各区域的
**可信占用量**，再结合步行通道、摆渡运力与临时封闭情况生成分流动作；支持值班人员在
暴雨、雷电或设备故障时**人工接管**，并保证恢复自动策略时**不会突然释放积压人群**。

仅依赖 Python 3.11+ 标准库，无第三方运行时依赖。

## 它解决的核心问题

过去运营靠经验发短信，常常“局部已经拥堵、上游仍在放行”。本服务：

- **上游联动**：入口放行额度不仅看入口自身，还看沿步行通道可达的下游区域。
  核心区红/橙时，入口同步收紧；通往拥堵区的通道被封闭到“无路可达”时在入口外硬截留。
- **可信占用量**：流量口径（闸机/摆渡）会漂移、快照口径（图像）会间歇，二者融合；
  数据源离线时占用量是“未知”而**不是猜成 0**，按失效安全处理。
- **预测只辅助**：停车入场/分时票只产生“建议”级动作，强制限流必须由已观测占用触发。
- **安全硬边界不可覆盖**：消防容量、特殊人群/返程专用通道、闭园返程保障是 `safety` 动作，
  人工接管无法压制或放宽。
- **渐进恢复**：限流放宽按固定台阶斜坡（默认 4 级 × 5 分钟）恢复，绝不一次性释放积压。
- **重启可恢复、决策可回放、结果确定**：所有输入与决策只追加到日志；重放同一日志 +
  同一时刻得到同一结果。

## 分层结构

| 文件 | 职责 |
|---|---|
| `src/domain.py` | 区域、通道、摆渡线、数据源画像、阈值、恢复参数的读取与校验；步行最短路（BFS）；运营阶段 |
| `src/events.py` | 原始事件校验与归一化（类型、时区、未来事件、负值等），非法消息隔离 |
| `src/occupancy.py` | 事件集合 → 各区域可信占用量、置信度、数据新鲜度、前瞻压力（纯函数、与到达顺序无关） |
| `src/policy.py` | 风险分级与分流动作（纯函数）：限流/截留、绕行、摆渡增能、返程疏散、斜坡恢复 |
| `src/overrides.py` | 人工接管：期限、理由、责任人校验；到期失效、撤销、当前视图折叠 |
| `src/store.py` | 追加式 JSONL 持久化（fsync） |
| `src/engine.py` | 编排：去重、归并、评估落盘、执行回执、重启恢复、跨日重置、决策链回放 |
| `src/api.py` | 标准库 HTTP 值班接口 + 周期评估定时器 |
| `src/demo.py` | 脚本化完整拥堵处置时间线（确定性演示） |

`fixtures/zones.json` 为区域与容量，`fixtures/site.json` 为通道/摆渡/数据源/阈值/
开闭园时间等资料。容量与时间均为本地开发示例，不代表任何真实景区。

## 运行

```bash
# 启动服务（默认每 60s 评估一次；--tick-seconds 0 关闭自动定时器）
python -m src.api --zones fixtures/zones.json --site fixtures/site.json \
    --journal data/run.jsonl --port 8080

# 先看一遍脚本化的完整拥堵处置（无需等待真实时钟）
python -m src.demo --clean
```

## HTTP 接口

| 方法/路径 | 说明 |
|---|---|
| `GET /health` | 存活与资料概况 |
| `GET /status` | 当前总体/分区风险、占用量、**数据新鲜度**、动作**依据**、执行回执、生效中的接管 |
| `POST /events` | 上报一批原始事件（可迟到/乱序/重复），返回 `{accepted, duplicates, quarantined}` |
| `POST /evaluate?now=...` | 立即评估；可显式传 `now`（ISO8601）用于演练/补算，`persist=0` 只试算不落盘 |
| `POST /overrides` | 新建人工接管（必须含 `override_id/kind/ttl_seconds/owner/reason/params`） |
| `POST /overrides/{id}/revoke` | 提前撤销（需撤销人、理由） |
| `POST /receipts` | 执行回执：`ack` → `executed` / `failed`，非法流转被拒 |
| `GET /replay?day=YYYY-MM-DD` | 回放某日完整决策链：事件、接管、每个评估时刻的决策、回执 |
| `GET /overrides` | 接管记录（生效中 + 已过期/已撤销） |

事件示例：

```json
{"event_id":"g-1001","source":"gate","type":"flow","zone":"waterfall",
 "value":15,"occurred_at":"2026-09-20T18:33:00+08:00"}
```

- `type=flow`：进出计数增量（入园 +、出园 -）。
- `type=snapshot`：区域在场人数绝对值（图像）。
- `type=lead`：前瞻压力（停车入场/分时票），不计入当前占用。

接管示例（雷电时人工压减入园节奏，30 分钟到期）：

```json
{"override_id":"storm-1","kind":"throttle","ttl_seconds":1800,
 "owner":"安全负责人-赵","reason":"雷电黄色预警",
 "params":{"zone":"gate-east","admit_per_interval":30}}
```

`kind` 还支持 `suppress_action`（压制某类**非安全**建议动作）与
`block_passage`（临时封闭/重开步行通道）。单次接管最长 24h，到期自动失效。

## 风险与动作语义

- 风险分级：黄 70% / 橙 85% / 红 95%（阈值见 `fixtures/site.json`）；占用超消防容量即红。
- 动作级别：`advisory`（建议，可被人工压制）与 `mandatory`；其中 `safety=true`
  （红色缺口限流、通道全封闭截留、闭园停入园、返程疏散）**永不被人工覆盖**。
- 占用未知（运营中有来源离线）：入口按最小额度保守放行（失效安全），同时发数据告警；
  开园冷启动全园无数据时不误报、不乱限流。
- 闭园后进入返程保障期（默认 1 小时）：停止入园、摆渡满负荷、启用特殊/返程通道；
  保障期结束后不再产生入园管控。跨运营日限流斜坡状态归零。

## 确定性、重启恢复与回放

- 引擎**不内置时钟**：`evaluate(now)` 由调用方给时刻，事件按 `occurred_at` 归并，
  因此重复投递、乱序到达、迟到事件最终都得到同一占用量与动作。
- 每条事件、接管、评估快照、回执都追加到 JSONL；重启时顺序读取即可恢复
  正在执行的措施、限流斜坡进度与当日回执。
- `GET /replay?day=...` 返回拥堵前后的完整决策链，含每个动作的 `reason` 与 `evidence`
  （占用、容量、比率、置信度、新鲜度、前瞻压力）。
